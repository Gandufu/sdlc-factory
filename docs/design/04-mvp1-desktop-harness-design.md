## 1. 目标

桌面工作台把已经在插件阶段验证的项目事实、OpenCode 会话和人工审核集成成多项目本地工作台。它不重新定义研发流程，不复制插件内部事实，也不通过界面操作绕过审核和版本规则。

主要目标：

- 管理多个本地项目和持续会话；
- 展示需求地图、业务模块和版本历史；
- 按业务模块组织需求、设计、编码和测试会话；
- 展示外部接口、环境配置和实际测试地址；
- 展示候选、审核、已批准版本和影响传播；
- 展示测试记录、Playwright 证据和系统测试报告；
- 提供恢复、诊断、成本和耗时视图；
- 保持用户显式执行和人工审核。

## 2. 产品形态

桌面端采用 Electron + React：

- Electron 主进程负责窗口、通知、本地文件选择和 Spring Boot 进程生命周期；
- React 渲染进程负责界面；
- Spring Boot 负责项目、会话目录、项目事实投影、审核和执行编排；
- OpenCode 负责模型、Skills、会话和工具调用；
- Factory 插件负责目标项目中的确定性事实和路径边界。

桌面端不能直接修改目标项目的审核、版本、执行或测试事实，所有写操作必须通过受控接口。

## 3. 权威边界

```text
目标项目
├─ Markdown 正文
├─ 结构化版本和审核事实
├─ 实施计划和执行记录
├─ 测试记录和证据
└─ Git 工作区
        ↓ 投影
Spring Boot
        ↓ 查询和受控命令
Electron + React
```

项目工作区是可移植事实源。桌面数据库只保存：

- 项目目录和打开状态；
- 会话目录和显示元数据；
- 可重建的需求地图和状态投影；
- 界面布局和筛选；
- 通知、耗时和模型调用统计；
- 最近活动索引。

删除桌面投影后，必须可以从目标项目恢复需求、设计、计划、候选、审核、版本和测试记录。

## 4. 主界面结构

桌面端采用三栏连续工作台：

```text
┌─────────────────┬──────────────────────────────┬──────────────────────┐
│ 项目与会话       │ 当前会话与人工审核            │ 项目事实与证据         │
│                 │                              │                      │
│ 项目             │ 对话                         │ 当前业务模块           │
│ 需求地图         │ 工具执行                     │ 输入版本               │
│ 业务模块会话     │ 候选差异                     │ 外部接口与环境         │
│ 系统测试会话     │ 审核操作                     │ 测试记录与报告         │
└─────────────────┴──────────────────────────────┴──────────────────────┘
```

推荐尺寸为 1440×900，最低可用尺寸为 1024×720。三栏允许调整宽度；较窄时右栏移动到中栏下方，但不得隐藏审核、失败和证据状态。

## 5. 全局导航

全局导航包含：

- 项目；
- 待处理；
- 运行；
- 需求地图；
- 环境与接口；
- 测试与验收；
- 设置。

“待处理”聚合待审核候选、失败、阻塞、失效版本和人工介入项。“运行”只读展示当前和历史执行，不允许通过拖拽改变正式状态。

## 6. 项目和会话

每个项目至少有：

- 项目主线会话；
- 产品概述与需求地图会话；
- 每个业务模块的需求会话；
- 每个业务模块的设计会话；
- 每个业务模块的编码会话；
- 每个业务模块的测试会话；
- 系统测试和验收会话；
- 必要的诊断和恢复会话。

会话可以跨多轮持续，但会话本身不代表项目阶段。切换会话时，系统根据目标业务模块和当前命令装配最小上下文。

会话列表显示：

- 会话名称和目标业务模块；
- 当前工作类型；
- 最近活动；
- 待审核、失败、阻塞或失效标记；
- 使用的输入版本；
- OpenCode 会话引用；
- 是否可以继续或需要重新装配上下文。

## 7. 需求地图

需求地图是桌面工作台的核心入口，显示不同类型节点：

- 业务模块；
- 外部接口；
- 全局和模块非功能需求；
- 产品概述和总需求版本。

关系使用不同样式区分：

- 执行依赖；
- 接口约束；
- 质量约束；
- 需求追溯；
- 变更影响。

地图支持：

- 选择历史总需求版本；
- 比较两个版本；
- 高亮新增、修改、退役和受影响节点；
- 点击节点查看修订时间线和内容差异；
- 跳转到对应需求、设计、测试说明和会话；
- 查看下游设计、代码和测试失效范围。

节点位置、缩放、颜色和折叠属于界面偏好，不创建需求版本。

## 8. 业务模块详情

右侧检查栏对当前业务模块展示：

- 模块目标和功能组；
- 模块需求当前版本；
- 模块设计和测试说明当前版本；
- 代码和测试结果当前版本；
- 依赖模块；
- 外部接口和非功能需求；
- 实施计划状态；
- 最近执行和测试记录；
- 开放问题、失败和阻塞；
- 唯一建议命令。

用户可以从同一位置进入需求、设计、编码或测试会话，但仍需显式输入完整 `/sdlc-*` 命令。

## 9. 候选和人工审核

中央会话区内嵌审核卡片，展示：

- 候选类型、编号和完整 SHA-256；
- 文件清单和变化摘要；
- 输入版本和来源；
- 内容差异；
- 确定性检查和独立预审；
- 影响分析；
- 测试记录和证据；
- 已知风险和开放问题。

审核操作包括：

- 通过；
- 退回修订并填写原因；
- 暂缓并记录关注项。

按钮操作只提交用户决定，Spring Boot 和项目插件重新验证候选编号、内容哈希和会话消息后才能创建已批准版本。

## 10. 设计和实施计划

设计视图分别显示：

- 产品总体设计；
- 当前模块设计；
- 相关接口设计；
- 当前模块测试说明；
- 总设计版本；
- 实施计划。

实施计划按业务模块显示顺序、依赖、输入版本、编码状态和测试状态。当前编码会话单独显示 OpenCode 编码待办清单，包括当前步骤、已完成步骤和未完成原因；命令结束时的单条“下一步待办”另行显示。两者都不与实施计划混合，也不能修改项目事实。

## 11. 环境和外部接口

环境视图展示：

- 开发、测试和生产环境；
- 环境配置版本和内容哈希；
- 应用地址、端口和就绪检查；
- 外部接口实际地址；
- 协议、证书和依赖版本；
- 凭据引用状态；
- 最近连通和契约测试；
- 失效和过期提示。

界面不得显示明文密码或访问令牌。测试记录只显示脱敏地址、令牌签发和过期状态。

## 12. 测试和验收

### 12.1 模块测试

模块测试页展示：

- 测试说明；
- 测试代码位置；
- 编译、静态检查、单元、集成和契约测试；
- 最近测试记录；
- 本次执行或证据复用；
- 失败日志摘要和证据位置；
- 模块测试结果审核。

### 12.2 系统测试

系统测试页按固定顺序显示：

```text
版本固定
→ 模块证据检查
→ 失效测试重跑
→ 应用启动与就绪
→ 外部接口检查
→ Playwright 跨模块流程
→ 报告生成
→ 系统验收审核
```

Playwright 场景显示步骤、结果、截图、视频和跟踪文件。原始大文件按需打开，不自动放入模型上下文。

### 12.3 测试报告

测试报告显示：

- 输入总需求和总设计版本；
- 参与业务模块；
- 环境和实际接口地址摘要；
- 模块测试结果；
- 本次执行和复用记录；
- Playwright 结果；
- 失败、跳过、阻塞和缺失证据；
- 人工检查项；
- 报告编号和 SHA-256。

报告由结构化测试记录生成，桌面端不能修改结论。

## 13. 运行、恢复和人工介入

运行视图展示：

- 命令和目标业务模块；
- OpenCode 会话；
- 输入版本和 Git 基点；
- 当前状态和持续时间；
- 工具执行、退出码和输出哈希；
- 测试记录和证据；
- 中止、失败和恢复原因。

同一根因或同一策略连续失败时，系统暂停并进入“待处理”，不无限重试。恢复必须创建新的执行记录并引用原失败记录，不覆盖历史。

## 14. 通知

桌面通知仅用于：

- 候选等待审核；
- 执行失败或阻塞；
- 需要登录、插入设备或确认外部环境；
- 测试环境不可用；
- 系统测试报告等待验收；
- 长时间运行结束。

通知不会自动批准、继续或执行下一命令。

## 15. 成本和可观测性

项目统计区分：

- 模型输入和输出量；
- 模型调用次数和持续时间；
- 测试执行时间；
- 本次执行和复用测试数量；
- Playwright 场景数量和失败率；
- 人工等待时间；
- 恢复和重复失败次数。

模型输入输出量不等于货币成本。没有计费证据时显示“未知”，不能显示为零成本。

## 16. 安全

- 渲染进程不直接访问 Node.js；
- 使用上下文隔离和受控消息桥；
- 主进程验证消息来源和参数；
- 目标项目路径必须由用户显式选择；
- 外部命令权限由 Spring Boot 和插件规则共同校验；
- 凭据使用系统安全存储或受控引用；
- 日志、截图和报告进行敏感信息检查；
- 桌面拖拽和快捷操作不能绕过审核和版本规则。

## 17. 验收条件

桌面阶段完成至少需要：

1. 可以导入、创建、关闭和重新打开本地项目；
2. 可以展示和比较需求地图历史版本；
3. 可以按业务模块持续需求、设计、编码和测试会话；
4. 可以查看候选差异并完成受控人工审核；
5. 可以展示外部接口实际地址和环境版本且不泄露凭据；
6. 可以查看模块测试记录和证据复用状态；
7. 可以执行并展示 Playwright 跨模块系统测试；
8. 可以从测试记录生成系统测试报告；
9. 删除桌面投影后可以从项目事实恢复；
10. Operations 视图保持只读，任何界面操作都不能绕过生命周期规则；
11. 1024×720 下仍可完成审核、查看失败和打开证据；
12. 应用重启后可以恢复项目、会话目录和待处理事项。

## 18. 当前状态

现有桌面原型和历史设计仍包含旧能力单元投影，只能作为视觉和交互参考，不能作为新领域合同。桌面实现必须等待插件阶段完成业务模块、需求地图、模块版本、环境配置和测试记录合同后再开始。
