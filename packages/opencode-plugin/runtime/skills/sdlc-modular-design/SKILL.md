# 模块化设计与测试说明

## 输入门槛

先调用 `sdlc_status`。目标模块需求、相关接口需求、非功能需求和总需求版本必须已经批准且当前有效。缺少门槛时停止，不得用草案继续设计。

## 工作方式

1. 使用 `sdlc_context_assemble` 装配当前模块最小上下文，不读取所有模块全文。
2. 产品总体设计只维护跨模块边界、运行、数据、信任、部署、失败恢复和系统测试原则。
3. 模块设计说明职责、接口、数据、状态、并发、错误、权限、实现路径、追溯、风险和替代方案。
4. 模块测试说明与设计同步维护，规定单元、模块集成、契约、必要界面测试、环境、通过条件和证据。
5. 模块设计候选必须同时包含 `design.md` 和 `verification-spec.md`，并结构化声明允许的产品路径和测试路径。
6. 外部接口设计描述协议、逻辑地址模板、认证、错误、兼容和契约测试；实际地址只进入环境版本。
7. 所有模块和接口设计批准后，使用 `sdlc_set_candidate_create` 生成精确总设计版本。

不得读取 `.sdlc-factory` 或 `.opencode` 内部文件，不得扫描无关子项目。需要目标脚手架事实时，只读取当前项目明确相关的配置、入口和目标模块路径，并在上下文记录纳入原因。

候选校验使用以下必要章节名：

- 产品总体设计：系统边界、模块关系、运行、数据、认证、部署、失败、系统测试、设计决定；
- 模块设计：输入版本、模块目标、范围、接口、数据、状态、错误、权限、实现路径、追溯、风险、修订；
- 接口设计：输入版本、协议、地址、请求、响应、认证、超时、错误码、演进、契约测试。

不创建能力单元、执行计划或新的项目级任务层。形成候选后原样采用候选工具返回的唯一审核命令并停止，不得继续提问或进入编码。
