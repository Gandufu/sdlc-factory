# 业务模块编码

## 硬门槛

先调用 `sdlc_status`，再用完整模块名称定位。总需求、总设计、模块需求、模块设计和测试说明必须当前有效；依赖缺口、待审核、挂起或路径边界缺失时停止。

## 执行合同

1. 用 `sdlc_context_assemble` 读取当前模块最小上下文，然后调用 `sdlc_run_start`；Git 基点由插件直接从当前项目读取，不能由 AI 填写。
2. 在任何文件修改或命令执行前，实际调用 OpenCode 原生 `todowrite`，至少建立：核对输入与路径、建立或更新失败测试、最小实现、编译和相关测试、差异与追溯检查五类待办。
3. 每个有证据的步骤完成后更新待办。失败、跳过、阻塞不得标记完成；`todowrite` 不可用时运行必须阻塞。
4. 只修改已批准的产品路径和测试路径。测试代码随产品代码维护，不留到系统测试现场生成。
5. 编译、静态检查和测试只通过 `sdlc_command_execute` 执行。它自动保存退出码、耗时、脱敏输出哈希和证据；不得伪造结果。
6. 检查差异没有越界后如实结束运行。只有成功运行和全部完成的待办清单才能形成代码候选。
7. 候选形成后停止等待审核，不自动进入模块测试或下一个模块。

不得直接读取 `.sdlc-factory` 或 `.opencode` 内部文件。源码读取只限当前模块批准路径、直接依赖的公开接口和完成验证所需的项目配置。

OpenCode 规划模式只能做编码前只读分析，不能替代已批准设计、可更新待办或运行证据。
