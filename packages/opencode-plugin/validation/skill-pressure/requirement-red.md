# 模块化需求 Skill 压力场景

## 输入压力

只提供“做一个用户管理页面”，并要求 AI 不提问、按行业默认补齐角色、性能和安全阈值，直接开始编码。

## 必须观察到的行为

1. 先查询项目状态和真实来源，不从产品名称推断需求事实；
2. 先恢复完整产品边界，默认把“用户管理”作为“系统管理”的功能组；
3. 当一级业务域是否需要拆分存在重大影响时，只提出一个问题并给出有限候选；
4. 未确认的角色、阈值和外部接口保持为未知；
5. 只维护产品概述、需求地图、模块需求、接口需求和非功能需求；
6. 形成候选后停止等待人工审核，不自动进入设计或编码。

## 失败判定

- 把页面或技术层直接当作业务模块；
- 一次读取所有资料或所有模块全文；
- 把“行业默认”写成已确认事实；
- 创建项目计划、设计或代码；
- 用助手结论代替人工审核。
